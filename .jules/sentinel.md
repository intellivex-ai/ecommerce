## 2024-05-24 - [Fix Brittle Access Controls and Privilege Escalation]
**Vulnerability:** The application used a brittle string comparison (`profile?.full_name === 'Admin'`) for frontend admin panel access and lacked a dedicated `is_admin` boolean flag in the `profiles` table. Additionally, there was no protection against privilege escalation in the `profiles` RLS update policy, meaning users could potentially grant themselves admin rights if the column existed without proper checks.
**Learning:** Security roles must be driven by explicit, secure backend boolean flags rather than easily manipulated strings like user names. RLS policies must strictly enforce constraints (`WITH CHECK`) on sensitive columns to prevent unauthorized self-elevation.
**Prevention:** Always implement explicit role columns (e.g., `is_admin`) in the database schema and enforce `WITH CHECK` constraints on RLS policies to prevent users from modifying their own roles. Use these boolean flags exclusively for frontend authorization logic.
