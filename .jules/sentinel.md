## 2025-04-13 - Insecure Direct Object Reference and Missing Admin Role
**Vulnerability:** The application currently relies on a client-side hardcoded check (`profile.full_name === 'Admin'`) to grant access to the admin dashboard. Furthermore, the Supabase RLS policies are overly permissive, such as allowing anyone to insert or update products (`Products can be inserted by anyone.`) and allowing anyone to update orders (`Anyone can update orders.`). It's missing a robust admin role definition or check on backend operations.
**Learning:** Hardcoded strings for admin authorization on the client side do not secure the backend. Missing row level security on sensitive operations like inserting/updating/deleting products, or fetching/updating orders leaves the system fully vulnerable to an attacker who just makes API requests.
**Prevention:** Implement an `is_admin` boolean flag on the `profiles` table. Enforce this via RLS on the database schema so that only genuine administrators can modify products, read all orders, or update order statuses.
